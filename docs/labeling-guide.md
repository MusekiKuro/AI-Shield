# Разметка тестовых диалогов

Нужно вручную написать 120 коротких вымышленных разговоров для проверки классификатора. Не вставляйте ответы генеративных моделей и настоящие звонки. Используйте только вымышленные имена; не указывайте настоящие телефоны, счета и названия банков. Набор не используется для обучения.

## 1. Состав набора

| Язык | `fraud` | `normal` | `hard_normal` | Всего |
|---|---:|---:|---:|---:|
| `ru` | 16 | 12 | 12 | 40 |
| `kk` | 16 | 12 | 12 | 40 |
| `mixed` | 16 | 12 | 12 | 40 |
| **Всего** | **48** | **36** | **36** | **120** |

`normal` — обычная беседа. `hard_normal` — тоже честная беседа, но в ней могут упоминаться опасные слова или прошлые мошенники. `fraud` — собеседник пытается обманом добиться действия.

## 2. Что записать

Один разговор — одна запись, от 4 до 14 реплик. Для каждой реплики укажите говорящего (`caller` или `customer`) и точный текст. Пишите естественно и добавляйте достаточно контекста, чтобы было понятно, кто чего хочет. `synthetic` всегда `true`: разговор выдуман, даже если его написал человек.

Одна JSON-запись выглядит так (в файле каждую запись пишут на отдельной строке):

```json
{"id":"test-001","language":"ru","synthetic":true,"kind":"fraud","segments":[{"speaker":"caller","text":"Здравствуйте, я из службы безопасности банка."},{"speaker":"customer","text":"Что произошло?"},{"speaker":"caller","text":"Срочно переведите деньги на безопасный счёт."},{"speaker":"customer","text":"Почему?"}],"request_seq":3,"target":{"scheme":"bank_security","active_request":true,"urgency":true,"secrecy":false,"safe_account_request":true,"evidence":["Срочно переведите деньги на безопасный счёт."]}}
```

Поля записи: `id` — `test-001`…`test-120`; `language` — `ru`, `kk` или `mixed`; `kind` — один из трёх видов выше; `segments` — реплики по порядку; `request_seq` — номер первой реплики с мошеннической просьбой, считая с 1 (`null` для `normal` и `hard_normal`). Внутри `target` заполните поля:

- `scheme`: `bank_security` — выдача себя за банк, полицию, следователя или техподдержку; `relative_in_trouble` — обман от имени родственника; `investment` — мошеннические инвестиции; `marketplace` — обман при покупке или продаже; `none` — обычный разговор или обсуждение обмана.
- `active_request`: `true`, если собеседник сейчас склоняет клиента к переводу денег, раскрытию кода или установке программы в рамках схемы; иначе `false`. Рассказ о прошлом, цитата, предупреждение и отказ без продолжающегося давления не активны.
- `urgency`: собеседник торопит именно с текущим действием. Может быть `true` и в обычной просьбе.
- `secrecy`: собеседник сейчас просит никому не рассказывать. Может быть `true` и без обмана.
- `safe_account_request`: просят перевести деньги на «безопасный», «защищённый» или «резервный» счёт.
- `evidence`: от 0 до 3 точных фрагментов текста, каждый не длиннее 120 символов; копируйте из одной реплики без исправлений и перевода. Для `normal`/`hard_normal` ставьте `scheme=none`, `active_request=false`, `safe_account_request=false`, `evidence=[]`. `urgency` и `secrecy` отмечайте по текущим просьбам.

## 3. Шесть разобранных примеров

Это короткие отрывки для объяснения меток; готовая запись всё равно должна содержать 4–14 реплик. В порядке указаны: `kind`; `request_seq`; `scheme`; `active_request / urgency / secrecy / safe_account_request`; `evidence`.

1. Caller: «Я из службы безопасности банка». Customer: «Что случилось?» Caller: «Срочно переведите на безопасный счёт и никому не говорите». → `fraud`; `3`; `bank_security`; `true / true / true / true`; `evidence=["Срочно переведите на безопасный счёт"]`.
2. Caller: «Я твой брат, новый номер». Customer: «Что произошло?» Caller: «Отправь код из SMS, никому не говори». → `fraud`; `3`; `relative_in_trouble`; `true / false / true / false`; `evidence=["Отправь код из SMS"]`.
3. Caller: «Верни долг сегодня, мне срочно платить за квартиру». Customer: «Хорошо, переведу на твой обычный счёт». → `normal`; `null`; `none`; `false / true / false / false`; `evidence=[]`. Срочность сама по себе не делает просьбу мошеннической.
4. Customer: «Вчера звонивший сказал: “Переведи на безопасный счёт и молчи”». Caller: «Хорошо, что ты отказался». Customer: «Я никому не сообщал код». → `hard_normal`; `null`; `none`; `false / false / false / false`; `evidence=[]`. Это рассказ и цитата, а не текущая просьба.
5. Caller: «Вложи деньги в нашу инвестицию, доход гарантирован». Customer: «Можно подумать?» Caller: «Да, но никому не рассказывай». → `fraud`; `3`; `investment`; `true / false / true / false`; `evidence=["Вложи деньги в нашу инвестицию"]`.
6. Caller: «Я курьер с маркетплейса». Customer: «Как оплатить?» Caller: «Внеси предоплату по ссылке в течение десяти минут». → `fraud`; `3`; `marketplace`; `true / true / false / false`; `evidence=["Внеси предоплату по ссылке"]`.

## 4. Как сдать

Без редактора кода заполните таблицу — одна строка на разговор, колонки: `id`, `language`, `synthetic`, `kind`, `segments`, `request_seq`, `scheme`, `active_request`, `urgency`, `secrecy`, `safe_account_request`, `evidence`. В ячейке `segments` пишите по одной реплике на строку как `caller — текст` или `customer — текст`, сохраняя порядок; булевы значения — `true`/`false`. В ячейке `evidence` — точные фрагменты, каждый с новой строки. Передайте таблицу координатору. Агент L1 перенесёт её в `data/evaluation/test.jsonl` только по отдельному поручению.
