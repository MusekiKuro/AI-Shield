## 2. Размещение

~~~text
Браузеры: клиент, доверенный, оператор, пульт демо
        │  HTTP + WebSocket
        ▼
ПРИЛОЖЕНИЕ (ноутбук)                        один процесс
  FastAPI + SQLite + собранный React
  правила риска, переводы, роли, события
        │  HTTP по закрытой сети, ключ в заголовке
        ▼
СЕРВЕР МОДЕЛЕЙ (университетский ПК, Windows, RTX 5080 16 ГБ)
  LLM  :8080  llama-server, Gemma 4 12B GGUF Q4   POST /v1/chat/completions
  STT  :8081  ml/serve/stt_server.py, Whisper     POST /v1/audio/transcriptions

ЗАПАСНОЙ LLM (ноутбук): Ollama, Qwen 4B           POST /v1/chat/completions
~~~

- Приложение знает модели только по адресам из конфигурации. Оба LLM-сервера говорят на одном OpenAI-совместимом протоколе, поэтому адаптер один.
- Приложение и сервер моделей могут стоять на одной машине: тогда адреса — `localhost`.
- Связь ноутбука с ПК — закрытая сеть (рекомендуется Tailscale). Порты моделей в открытый интернет не выставляются; серверы требуют ключ.
- На ПК стоит Windows. Серверы моделей запускаются в самой Windows, чтобы порты были видны по закрытой сети; дообучение идёт в WSL2.
- Ожидаемая занятость видеопамяти: Gemma 4 12B Q4 около 8 ГБ, Whisper turbo около 2 ГБ на модель. Это оценка, не замер.

## 3. Цепочка отказов классификатора

Порядок попыток при каждой оценке:

1. Основной LLM (`LLM_BASE_URL`) → `source=llm`.
2. Запасной LLM (`LLM_FALLBACK_BASE_URL`), если он задан и в бюджете осталось не меньше 1000 мс → `source=llm`.
3. Словарь → `source=dictionary`.
4. Ничего не сработало → `status=unknown`, `source=none`.

Общий бюджет подтверждения перевода — `DECISION_TIMEOUT_MS=3000`. Поле `model` в результате называет модель, которая реально ответила. Интерфейс показывает источник и модель как есть.

## 4. Контракт классификатора

Единственный источник истины для адаптера, обучающих данных и замеров.

### 4.1. Вход модели

- Системное сообщение: содержимое `backend/app/speech/classifier_prompt.txt`, без изменений. Его же читают скрипты обучения и замеров.
- Сообщение пользователя: окно разговора. Каждый сегмент — отдельная строка с префиксом `— `. Метки говорящих в текст не входят: в голосовом режиме их нет.
- Окно: последние 40 сегментов, не длиннее 6000 символов; лишнее отрезается с начала.
- Параметры: `temperature=0`, структурированный вывод по схеме 4.2 через `response_format`, режим размышлений выключен.

### 4.2. Выход модели

~~~json
{
  "scheme": "bank_security",
  "active_request": true,
  "urgency": true,
  "secrecy": true,
  "safe_account_request": true,
  "evidence": ["переведите все средства на безопасный счёт"]
}
~~~

Порядок ключей фиксирован. Схема лежит в `backend/app/speech/llm_schema.json`.

| Поле | Значение |
|---|---|
| `scheme` | `bank_security` \| `relative_in_trouble` \| `investment` \| `marketplace` \| `none`. Звонки «от полиции/следователя» относятся к `bank_security` |
| `active_request` | Собеседник прямо сейчас склоняет клиента к переводу, раскрытию кода или установке программы в рамках мошеннической схемы |
| `urgency` | Собеседник торопит с действием. Бывает `true` и в обычной просьбе |
| `secrecy` | Собеседник просит никому не рассказывать |
| `safe_account_request` | Просьба перевести деньги на «безопасный», «защищённый», «резервный» счёт |
| `evidence` | От 0 до 3 дословных фрагментов разговора, каждый до 120 символов |

Рассказ о мошенниках, цитата, предупреждение и отказ клиента — это `active_request=false`.

Модель выделяет признаки. Уровень риска и судьбу перевода определяет `risk/engine.py`.

### 4.3. Обработка ответа в адаптере

- Ответ разбирается и проверяется по схеме. Невалидный ответ считается отказом этой ступени цепочки.
- Каждый фрагмент `evidence` должен быть подстрокой окна после нормализации пробелов. Фрагменты, которых нет в тексте, отбрасываются.
- Результат дополняется до `SpeechAssessment` из C03.3: `status`, `source`, `model`, `session_id`, `segment_seq`, `received_at`.
- Текст разговора — данные. Инструкции внутри него адаптер и подсказка игнорируют.

## 5. Контракт распознавания речи

### 5.1. Путь звука

1. Браузер записывает микрофон в PCM 16 кГц моно.
2. Запись режется на фразы: по паузе от 600 мс либо по достижении 8 секунд.
3. Каждая фраза кодируется в WAV и отправляется: `POST /api/dialogues/{id}/audio`, multipart-поля `seq` (целое, с 1), `language` (`ru` \| `kk` \| `auto`), `audio` (файл).
4. Сервер приложения пересылает звук на STT, получает текст и добавляет его в `DialogueService` как финальный сегмент с `speaker=unknown`.
5. Ответ: `{"seq": 3, "text": "...", "language": "kk"}`. Пустой текст сегмент не создаёт.

Звук живёт только в памяти на время запроса. Промежуточного текста нет: пока фраза распознаётся, интерфейс показывает состояние «распознаётся».

Маршрут `POST /api/stt/token` из прежнего плана отменён.

### 5.2. Сервер STT

`POST /v1/audio/transcriptions`, multipart: `file`, `language` (необязательно). Ответ: `{"text": "...", "language": "kk", "duration_ms": 4200}`. Заголовок `Authorization: Bearer <STT_API_KEY>`.

Модели задаются переменными окружения сервера STT:

- `STT_MODEL_DEFAULT` — исходный Whisper turbo; определяет язык и распознаёт русский.
- `STT_MODEL_KK` — казахская дообученная версия (кандидат: `issai/whisper-turbo`). Если задана, фразы на казахском распознаются ею.

При `language=auto` язык определяет модель по умолчанию. Нужна ли вторая модель, решает замер M10.

## 8. Три уровня агентов

| Уровень | Что получает | Признак задачи |
|---|---|---|
| L3, высший | Контракты, деньги, права, состояния, конкурентный доступ, адаптер LLM, обучение, сборка экранов | Решение затрагивает несколько модулей или цену ошибки нельзя увидеть по одному файлу |
| L2, средний | Самостоятельный модуль по готовому контракту; всё, где важно качество казахского языка | Несколько связанных функций в своих файлах, контракт уже записан |
| L1, мелкий | Один файл по точной карточке | Вход и выход перечислены, проектировать нечего |

Правила для всех уровней:

- Каждый исполнитель пишет только файлы своей карточки. Контракты из разделов 4–6 и общие файлы меняет только L3.
- Если контракта не хватает, исполнитель L1/L2 останавливается и описывает блокер.
- К каждому поручению L1 и L2 прикладывается блок из [flash-tasks.md](./superpowers/plans/2026-11-11-flash-tasks.md), раздел «Блок, который нужно приложить к каждой карточке», плюс ссылка на этот документ.
- Скрипты замеров и обучения агент пишет, а запускает пользователь на ПК. Цифры в документах появляются только из файлов `ml/eval/reports/`.

## 10. Открытые вопросы

- Будет ли ПК включён и доступен по сети в день защиты. Если нет, защита идёт на запасной модели с ноутбука и записанном ролике.
- Качество Gemma 4 12B и Whisper на казахском: неизвестно до M10.1.
- Точный идентификатор казахского Whisper на Hugging Face: проверить при скачивании; запасной кандидат — `abilmansplus/whisper-turbo-ksc2`.
- Формат сдачи и критерии организаторов.
