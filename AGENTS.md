# Правила проекта «ИИ-щит»

## Текущий способ работы

- С 12 ноября 2026 задачи выполняют агенты трёх уровней: L3 высший, L2 средний, L1 мелкий. Распределение и волны — в docs/ARCHITECTURE.md, разделы 8–9.
- Агентов и чаты запускает пользователь и сам выдаёт каждому карточку. Наличие карточки не разрешает агенту запускать других агентов или новые чаты.
- Координатор — агент L3, которому пользователь поручил общие контракты и очередь.
- Не менять выбранную модель главного агента.
- При последующем запросе на разработку/запуск сабагентов без указанного режима действует личное правило пользователя: один вопрос «Режим: 1 — Качество, 2 — Скорость?» и ожидание ответа. Явное указание пользователя работать без выбора имеет приоритет.
- Для collaboration.spawn_agent при явном разрешении: fork_turns="none", краткое ТЗ, точные файлы и запреты. Разведка и мелкие правки — gpt-6-luna/high; основная разработка в режиме качества — gpt-6.1-sol/medium. Именованную роль использовать только при точном совпадении настроек; иначе default с явными model/reasoning_effort.
- Возврат к тем же файлам по возможности поручать прежнему исполнителю. При совместной работе нельзя отменять чужие изменения.

## Перед работой

Прочитать docs/MVP_SCOPE.md, docs/ARCHITECTURE.md и соответствующую карточку из docs/superpowers/plans/.
docs/ARCHITECTURE.md — актуальное устройство системы, контракты моделей и уровни агентов L1–L3; при расхождении с ранними планами действует он.
Основной план: docs/superpowers/plans/2026-11-11-mvp-implementation.md.
TASKS.md отражает очередь, PROJECT_STATE.md — краткий контекст.

Критерии карточек описывают желаемое поведение и не разрешают автоматические проверки. При поручении только на план не начинать программную реализацию автоматически. В разрешённом объёме координатор берёт следующие ready-задачи без промежуточных вопросов.

## Обязательные ограничения

- Не писать и не запускать тесты без прямого поручения пользователя.
- Скрипты замеров и обучения из ml/ агенты пишут, запускает их пользователь на ПК с видеокартой.
- Не запускать линтеры, тайпчекеры, форматтеры и проверочные сборки после правок.
- Не выполнять саморевью и не вызывать reviewer без прямого запроса.
- Не превращать правила навыков в дополнительные паузы согласования.
- После записи требуемых файлов исполнитель возвращает краткий результат. Не выдавать написанный код за проверенный.
- Не делать автоматическую публикацию, отправку материалов или сообщения другим чатам.
- В конце каждого поручения кодеру/помощнику добавлять:
  CRITICAL: Do NOT write or run tests, linters, typecheckers, or self-reviews. Only implement the requested file changes and return immediately.

## Владение файлами

- L3: API, схемы, зависимости, деньги, роли, статусы, интеграция экранов, контракты моделей.
- L1 и L2: только пути своей карточки; контракты, скоринг и чужие файлы остаются за L3. При нехватке контракта — остановиться и описать блокер.
- TASKS.md и PROJECT_STATE.md редактирует только координатор, один раз в конце сессии.
- PROJECT_STATE.md: дата, ветка, цель, изменённые файлы, блокеры и один следующий шаг.
- TASKS.md: ID, Приоритет, Задача и границы, Статус, Владелец, Файлы. Статусы: proposed, ready, in_progress, blocked, done; review только по запросу пользователя.

## Продуктовые границы

Только синтетическое банковское демо. Сервер решает судьбу перевода.
Настоящие звонки сторонних приложений не перехватываются; обработка идёт на сервере команды, и это обозначается.
Полные тексты, аудио, PIN и ключи не попадают в логи или Git.
Результат с неизвестным качеством нельзя представлять измеренной вероятностью.
